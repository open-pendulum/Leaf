### 核心知识点记录

#### 1. 渲染管线中的三大变换矩阵

在 3D 渲染中，顶点从模型空间到屏幕空间经历三重变换：

```
最终位置 = ProjectionMatrix × ViewMatrix × ModelMatrix × 顶点位置
```

- **Model Matrix（模型矩阵）**：物体自身的变换
  - 平移：`glm::translate(mat4(1.0f), pos)` - 物体在世界坐标中的位置
  - 旋转：`glm::rotate(mat4(1.0f), angle, axis)` - 物体的旋转
  - 缩放：`glm::scale(mat4(1.0f), scale)` - 物体的大小
  - 组合：`T × R × S`（注意顺序：先缩放、再旋转、最后平移）

- **View Matrix（视图矩阵）**：相机视角
  - 也就是正交相机的 `RecalculateViewMatrix()` 计算的结果
  - 逻辑上"相机移动"，数学上"世界反向移动"

- **Projection Matrix（投影矩阵）**：从 3D 投影到 2D 屏幕空间
  - 在 `OrthographicCamera` 构造时确定：`glm::ortho(left, right, bottom, top, -1.0f, 1.0f)`

#### 2. Uniform 变量的命名规范与作用域

**命名统一性**：
- 在 shader 中定义 uniform 名称时，需要与 C++ 代码中的上传名称完全一致
- 当前约定：
  - `u_ViewProjection`：相机视角（View × Projection 的组合）
  - `u_Transform`：每个物体独立的模型变换（Model）

**作用域**：
- `u_ViewProjection`：在 `Renderer::BeginScene` 时上传一次，所有绘制共享
- `u_Transform`：在 `Renderer::Submit` 时每次绘制都上传，每个物体不同

**代码实现**：
```cpp
// Renderer::Submit 中上传两个矩阵
shader->UploadUniformMat4("u_ViewProjection", sSceneData->ViewProjectionMatrix);
shader->UploadUniformMat4("u_Transform", transform);
```

**Shader 中的对应**：
```glsl
uniform mat4 u_ViewProjection;
uniform mat4 u_Transform;

void main() {
    gl_Position = u_ViewProjection * u_Transform * vec4(a_Position, 1.0);
}
```

#### 3. 批量绘制的实现思路

**问题**：绘制 400 个相同的小方块（20x20 网格），如何高效实现？

**方案对比**：

1. **方案 A（当前实现）**：循环调用 DrawCall
   - 优点：简单直观，每个方块可独立变换
   - 缺点：400 次 DrawCall，性能较低
   - 代码示例：
   ```cpp
   glm::mat4 scale = glm::scale(glm::mat4(1.0f), glm::vec3(0.1f));
   for (int y = 0; y < 20; y++) {
       for (int x = 0; x < 20; x++) {
           glm::vec3 pos(x * 0.11f, y * 0.11f, 0.0f);
           glm::mat4 transform = glm::translate(glm::mat4(1.0f), pos) * scale;
           Leaf::Renderer::Submit(mBlueShader, mSquareVertexArray, transform);
       }
   }
   ```

2. **方案 B（后续优化）**：实例化渲染（Instancing）
   - 使用 `glDrawArraysInstanced`，一次 DrawCall 渲染多个实例
   - 需要额外传递每个实例的变换矩阵

3. **方案 C（高级）**：批渲染（Batch Rendering）
   - 将多个物体的顶点数据合并到一个大 Buffer
   - 一次 DrawCall 完成所有绘制
   - 需要动态管理 Buffer 大小和更新

**当前方案的意义**：
- 作为学习和理解的过渡版本
- 清晰展示"同一 Geometry，不同 Transform"的概念
- 为后续优化奠定基础

#### 4. 顶点属性的扩展：从位置到颜色

**顶点数据结构变化**：
```cpp
// 原版本：只有位置
float vertices[] = {
    -0.5f, -0.5f, 0.0f,  // position
    0.5f,  -0.5f, 0.0f,
    0.5f,  0.5f,  0.0f,
    -0.5f, 0.5f,  0.0f,
};

// 新版本：位置 + 颜色
float vertices[3 * 7] = {
    -0.5f, -0.5f, 0.0f,  0.8f, 0.2f, 0.8f, 1.0f,  // position (3) + color (4)
    0.5f,  -0.5f, 0.0f,  0.2f, 0.3f, 0.8f, 1.0f,
    0.0f,  0.5f,  0.0f,  0.8f, 0.8f, 0.2f, 1.0f,
};
```

**BufferLayout 配置**：
```cpp
Leaf::BufferLayout layout = {
    {Leaf::ShaderDataType::Float3, "aPos"},    // location = 0
    {Leaf::ShaderDataType::Float4, "aColor"},  // location = 1
};
```

**Shader 中的对应**：
```glsl
layout(location = 0) in vec3 aPos;
layout(location = 1) in vec4 aColor;

uniform mat4 u_ViewProjection;
uniform mat4 u_Transform;

out vec3 outPosition;
out vec4 outColor;

void main() {
    outPosition = aPos;
    gl_Position = u_ViewProjection * u_Transform * vec4(aPos, 1.0);
    outColor = aColor;  // 传递到片元着色器
}
```

#### 5. GLM 变换函数的使用

**关键头文件**：
```cpp
#include <glm/gtc/matrix_transform.hpp>  // glm::translate, glm::rotate, glm::scale
```

**常用变换**：
```cpp
// 单位矩阵（起始点）
glm::mat4 identity = glm::mat4(1.0f);

// 平移
glm::mat4 translate = glm::translate(glm::mat4(1.0f), glm::vec3(1.0f, 2.0f, 3.0f));

// 旋转（角度为弧度）
glm::mat4 rotate = glm::rotate(glm::mat4(1.0f), glm::radians(45.0f), glm::vec3(0, 0, 1));

// 缩放
glm::mat4 scale = glm::scale(glm::mat4(1.0f), glm::vec3(0.1f));  // 缩小到 0.1 倍

// 组合变换：先缩放、再平移
glm::mat4 transform = translate * scale;
```

**注意点**：
- 矩阵乘法顺序从右到左：`translate * scale` 意味着"先应用 scale，再应用 translate"
- 旋转角度使用弧度而非角度，需要 `glm::radians()` 转换

## Debug 记录与问题解决

### 问题 1：三角形显示为黑色且位置异常

**现象**：
- 三角形显示为黑色（而不是 Hazel 的彩色渐变）
- 三角形位置异常（斜的，不在正中间）
- 蓝色方块网格显示正常

**与 Hazel 的对比**：
- Hazel：彩色渐变三角形（紫色→蓝色→黄色）在正中间
- 我的代码：黑色斜三角形

**排查过程**：

#### 子问题 1.1：Vertex shader 使用错误变量

**错误代码**：
```glsl
void main() {
    v_Position = a_Position;
    v_Color = a_Color;
    gl_Position = u_ViewProjection * u_Transform * vec4(v_Position, 1.0);  // ❌ 错误
}
```

**正确代码**：
```glsl
void main() {
    v_Position = a_Position;
    v_Color = a_Color;
    gl_Position = u_ViewProjection * u_Transform * vec4(a_Position, 1.0);  // ✅ 正确
}
```

**问题分析**：
- `a_Position` 是**输入变量**（attribute），包含顶点的原始位置
- `v_Position` 是**输出变量**（varying），用于传递给片元着色器
- 计算 `gl_Position` 时应该直接使用 `a_Position`，而不是 `v_Position`
- 虽然先赋值了 `v_Position = a_Position`，但这不是正确的做法

#### 子问题 1.2：OpenGLVertexArray 缺少 index++（最关键的 bug）

**根本原因**（导致所有问题的核心）：
`OpenGLVertexArray::AddVertexBuffer()` 中缺少 `index++`，导致所有属性都被分配到 location 0。

**错误代码**：
```cpp
uint32_t index = 0;
for (auto &element : layout) {
    glEnableVertexAttribArray(index);
    glVertexAttribPointer(index, element.GetComponentCount(),
                          ShaderDataTypeToOpenGLBaseType(element.type),
                          element.normalized ? GL_TRUE : GL_FALSE,
                          layout.GetStride(), (const void *)element.offset);
    // ❌ 缺少 index++;
}
```

**正确代码**：
```cpp
uint32_t index = 0;
for (auto &element : layout) {
    glEnableVertexAttribArray(index);
    glVertexAttribPointer(index, element.GetComponentCount(),
                          ShaderDataTypeToOpenGLBaseType(element.type),
                          element.normalized ? GL_TRUE : GL_FALSE,
                          layout.GetStride(), (const void *)element.offset);
    index++;  // ✅ 递增 index
}
```

**导致的问题**：
1. 所有属性都被分配到 location 0
2. `a_Position` 和 `a_Color` 冲突
3. 顶点数据错位：
   - 位置属性读取到错误的数据（部分颜色数据被当作位置）
   - 颜色属性读取到错误的数据（部分位置数据被当作颜色）
4. 位置异常（三角形变斜）
5. 颜色异常（显示黑色）

**为什么蓝色方块正常？**
- 蓝色方块的顶点数据只有位置（3 个 float），没有颜色
- 所以属性冲突对蓝色方块的影响较小
- 而且 blueShader 的 fragment shader 直接输出固定颜色，不使用 `v_Color`

**为什么三角形异常严重？**
- 三角形的顶点数据有位置 + 颜色（7 个 float）
- 属性冲突导致位置和颜色数据错位
- Triangle fragment shader 使用 `v_Color`，但 `v_Color` 读取到的是错误数据
- 位置错误导致三角形变斜
- 颜色错误导致显示黑色

**修复顺序**：
1. 首先修复 `index++` 问题（这是根本原因）
2. 然后修复 vertex shader 中使用 `a_Position` 而不是 `v_Position`

**修复位置**：
`/d/workspace/Leaf/Leaf/platform/opengl/OpenGLVertexArray.cpp` 第 70 行添加 `index++;`

#### 子问题 1.3：蓝色方块 shader 多余属性（次要问题）

虽然蓝色方块显示正常，但其 shader 中仍有多余的颜色属性：

**当前代码**：
```glsl
// blueShaderVertexSrc
layout(location = 0) in vec3 a_Position;
layout(location = 1) in vec4 a_Color;  // ❌ 多余的属性

uniform mat4 u_ViewProjection;
uniform mat4 u_Transform;

out vec3 v_Position;
out vec4 v_Color;  // ❌ 多余的输出
```

**Hazel 代码**：
```glsl
// blueShaderVertexSrc
layout(location = 0) in vec3 a_Position;

uniform mat4 u_ViewProjection;

out vec3 v_Position;
```

**分析**：
- Hazel 的 blueShader 没有 `a_Color` 和 `v_Color`
- 因为 `squareVertices` 只有位置数据（3 个 float），不需要颜色属性
- 当前代码中的多余属性虽然不影响显示（因为 fragment shader 不使用 `v_Color`），但是是不正确的

**建议修复**：
```glsl
// blueShaderVertexSrc（修正后）
layout(location = 0) in vec3 a_Position;

uniform mat4 u_ViewProjection;
uniform mat4 u_Transform;

out vec3 v_Position;

void main()
{
    v_Position = a_Position;
    gl_Position = u_ViewProjection * u_Transform * vec4(a_Position, 1.0);
}
```

### 问题 2：理解 Hazel shader 中的颜色覆盖逻辑

**背景**：
在阅读 Hazel 的 fragment shader 代码时，发现第 86 行和第 87 行似乎有冲突。

**代码**：
```glsl
void main()
{
    color = vec4(v_Position * 0.5 + 0.5, 1.0);  // 第 86 行
    color = v_Color;                            // 第 87 行（覆盖上一行）
}
```

**执行流程分析**：

**第 86 行：计算基于位置的渐变色**
- 公式：`v_Position * 0.5 + 0.5` 将位置从 [-1, 1] 映射到 [0, 1]
- 例如：
  - 左下角 (-0.5, -0.5, 0.0) → (0.0, 0.0, 1.0) 蓝色
  - 右下角 (0.5, -0.5, 0.0) → (0.5, 0.0, 1.0) 紫蓝色
  - 右上角 (0.0, 0.5, 0.0) → (0.5, 0.75, 1.0) 浅蓝紫色

**第 87 行：用顶点颜色覆盖**
- `v_Color` 来自 vertex shader 传递的顶点颜色
- 完全覆盖第 86 行的结果
- 顶点 0：紫色 (0.8, 0.2, 0.8, 1.0)
- 顶点 1：蓝色 (0.2, 0.3, 0.8, 1.0)
- 顶点 2：黄色 (0.8, 0.8, 0.2, 1.0)

**最终效果**：
Hazel 显示的"渐变色"实际上是**顶点颜色的插值**，而不是第 86 行的基于位置的渐变色！

```
顶点颜色插值（实际显示的效果）：
         黄色 (0.8, 0.8, 0.2)
              /\
             /  \
            /    \
   紫色 (0.8, 0.2, 0.8) -------- 蓝色 (0.2, 0.3, 0.8)
```

**验证第 86 行无用**：
如果删除第 86 行，效果完全一样：
```glsl
void main()
{
    color = v_Color;  // 只保留顶点颜色
}
```

**如果想看第 86 行的效果**：
删除第 87 行：
```glsl
void main()
{
    color = vec4(v_Position * 0.5 + 0.5, 1.0);  // 只保留位置渐变
}
```
这样会显示基于位置的渐变（蓝色系），而不是顶点颜色的插值。

**对比表格**：
| 代码 | 效果 |
|------|------|
| `color = v_Position * 0.5 + 0.5; color = v_Color;` | 三色渐变（紫色→蓝色→黄色）|
| `color = v_Color;` | 三色渐变（紫色→蓝色→黄色）|
| `color = v_Position * 0.5 + 0.5;` | 位置渐变（蓝色系）|

**结论**：
Hazel 的代码中第 86 行是**无用代码**，可能保留用于：
1. 调试目的
2. 教学演示"被覆盖"的概念
3. 遗留的代码未清理

在实际项目中，应该删除无用代码以提高代码可读性和可维护性。

### 调试总结

**实际问题分析**：
- 最初问题：三角形显示为黑色且位置异常，蓝色方块正常
- 根本原因：`OpenGLVertexArray` 缺少 `index++`，导致所有属性分配到 location 0
- 影响范围：
  - 三角形：严重（有位置 + 颜色两个属性，冲突导致数据错位）
  - 蓝色方块：轻微（只有位置属性，且 fragment shader 输出固定颜色）

**按重要性排序的问题**：
1. ❌❌❌ **OpenGLVertexArray 缺少 index++**（最关键，导致所有属性冲突）
2. ❌❌ **三角形 shader 使用 v_Position 而不是 a_Position**（次要，但在 index++ 修复后才显现）
3. ℹ️ **蓝色方块 shader 多余属性**（不影响显示，但是不正确的代码）
4. ℹ️ **shader 颜色覆盖逻辑理解**（不影响功能，只是理解问题）

**修复顺序建议**：
1. **优先修复** `OpenGLVertexArray` 的 `index++` 问题（这是根本原因，修复后大部分问题自动解决）
2. 修复 vertex shader 中使用 `a_Position` 而不是 `v_Position`
3. 清理 blueShader 中的多余属性（可选，但推荐）

**经验教训**：
- 检查顶点属性时，要确保每个属性有正确的 location（通过 index++ 实现）
- Vertex shader 中计算 gl_Position 必须使用输入变量（attribute），而不是输出变量（varying）
- 当多个属性冲突时，有多个属性的对象受影响更严重
- Shader 中被覆盖的代码可能是无用的，但需要理解其意图（如 Hazel 的 fragment shader）
- 排查渲染问题时，优先检查顶点属性的 location 分配是否正确
