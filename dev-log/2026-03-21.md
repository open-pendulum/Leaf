### 核心知识点记录

#### 1. OpenGL混合（Blending）系统

**透明渲染原理**：
```cpp
void OpenGLRendererAPI::Init() {
    // 启用混合功能，用于透明渲染
    glEnable(GL_BLEND);

    // 设置混合函数：
    // GL_SRC_ALPHA: 使用源片段的alpha值
    // GL_ONE_MINUS_SRC_ALPHA: 使用 (1 - 源片段alpha值)
    glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);
}
```

**混合计算公式**：
```
result_color = source_color * source_alpha + destination_color * (1.0 - source_alpha)
```

#### 2. 纹理坐标系统

**纹理坐标系**：
- OpenGL纹理坐标系与图片坐标系不同
- 左下角为(0, 0)，右上角为(1, 1)
- 标准化坐标，不依赖纹理实际尺寸

**纹理映射原理**：
```cpp
// 顶点数据：位置 + 纹理坐标
float vertices[5 * 4] = {
    -0.5f, -0.5f, 0.0f, 0.0f, 0.0f,  // 左下：位置 + 纹理坐标(0,0)
    0.5f,  -0.5f, 0.0f, 1.0f, 0.0f,  // 右下：位置 + 纹理坐标(1,0)
    0.5f,  0.5f,  0.0f, 1.0f, 1.0f,  // 右上：位置 + 纹理坐标(1,1)
    -0.5f, 0.5f,  0.0f, 0.0f, 1.0f   // 左上：位置 + 纹理坐标(0,1)
};
```

#### 2. 顶点属性Location分配

**关键修复**：从局部变量到成员变量的改进
```cpp
// 修改前：使用局部变量，每次调用都重置为0
uint32_t index = 0;  // 每次AddVertexBuffer都重置
for (auto &element : layout) {
    // ... 使用局部变量index ...
    // 缺少持久化，导致索引重复
}

// 修改后：使用成员变量，确保索引持续递增
uint32_t mVertexBufferIndex = 0;  // 作为成员变量
for (auto &element : layout) {
    glEnableVertexAttribArray(mVertexBufferIndex);
    // ...
    mVertexBufferIndex++;  // ✅ 关键修复：持续递增，确保唯一性
}
```

**影响**：
- 成员变量确保多个VertexBuffer添加时索引不重复
- 避免所有属性都被分配到location 0的问题
- 支持更复杂的顶点布局配置

- **ShaderLibrary的核心优势**：
  - **统一管理**：所有着色器集中管理，避免重复创建
  - **按需加载**：支持延迟加载，提高启动速度
  - **命名访问**：通过名称快速获取着色器实例
  - **资源复用**：多个组件可共享同一个着色器实例

#### 3. 矩阵变换管线

**渲染管线中的变换**：
```
最终位置 = u_ViewProjection × u_Transform × vec4(a_Position, 1.0)
```

**矩阵作用**：
- `u_ViewProjection`：相机视图投影矩阵（每帧统一）
  - 由OrthographicCamera计算得到
  - 包含相机位置、旋转、投影信息
- `u_Transform`：模型变换矩阵（每个物体独立）
  - 包含物体的平移、旋转、缩放
  - 使用GLM库进行矩阵运算

**工厂模式实现**：
```cpp
Shader* Shader::Create(const std::string& vertexSrc,
                       const std::string& fragmentSrc) {
    switch (Renderer::GetAPI()) {
    case RendererAPI::API::OpenGL:
        return new OpenGLShader(vertexSrc, fragmentSrc);
    default:
        LEAF_CORE_ASSERT(false, "Unknown RendererAPI!");
        return nullptr;
    }
}
```

**优势**：

- 客户端代码无需关心具体实现
- 符合开闭原则

**现象**：
- 左上半部分显示为同一个颜色
- 棋格纹理没有正确交错显示

**原因分析**：
- 顶点属性location分配错误
- OpenGLVertexArray中缺少index++
- 纹理坐标和位置数据冲突

**解决方案**：
1. 修复OpenGLVertexArray.cpp中的index++问题
2. 确保每个顶点属性正确分配到对应location
3. 验证纹理坐标定义正确性

**经验教训**：
- OpenGL中顶点属性必须递增分配location
- 多个属性冲突时，包含多个属性的对象受影响更严重
- 纹理坐标错误会导致整个纹理显示异常
